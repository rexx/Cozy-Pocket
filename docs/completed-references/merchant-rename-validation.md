# 商家名稱調整驗證與回饋完成紀錄

本項目補齊商家名稱調整的驗證、合併提示與操作後狀態，避免商家名稱正規化後產生重複商家，並讓預覽、更名、同步結果在商家管理頁中有一致的回饋位置。

## 完成內容

- `normalizeMerchantName` 會移除前後空白並合併連續空白，避免只因空白差異造成商家分組分裂。
- 商家彙整、商家交易查詢與更名影響範圍使用正規化後的大小寫不敏感 key 比對；顯示與寫回仍保留既有商家名稱或使用者輸入的正規化名稱。
- `MerchantRenamePreview` 加入 `normalizedInput`、`willMerge` 與 `mergeTargetMerchant`，讓 UI 能清楚區分一般更名與合併到既有商家。
- 預覽錯誤、預覽資訊、合併警告與完成結果共用同一個 feedback card 樣式，只依 `error`、`warning`、`success` tone 調整顏色。
- 新名稱輸入變更後會同步清除既有預覽與錯誤訊息，避免舊訊息套用到新的輸入值。
- 操作順序固定為「預覽影響筆數」→「訊息 / 警告 / 資訊」→「確認更名」；確認按鈕只在有效預覽後顯示。
- 更名送出時確認按鈕會顯示旋轉 loading icon，避免只靠文字提示。
- 更名完成後表單不會整個消失，而是直接選到新商家或合併目標商家，清空輸入與預覽後重新載入相關交易。
- 離線或同步部分失敗時，已更新的交易仍會保留 `pending` 狀態供後續同步，頁內訊息會顯示對應結果。

## 介面與資料

- 沒有新增商家資料表；商家名稱仍儲存在每筆 `Transaction.merchant`。
- 商家更名仍以批次更新交易完成，受影響交易會更新 `updatedAt`、遞增 `version`，並將 `syncStatus` 設為 `pending`。
- 預覽、錯誤與完成結果訊息位於新名稱輸入區下方的固定回饋區，不會被相關交易列表推到頁面底部。

## 驗證

- 已執行 `npm run build`。
- 手動驗證空白名稱、同名、找不到商家、合併到既有商家與成功更名。
- 手動驗證新名稱輸入變更後會同時清除黃色預覽卡與紅色錯誤卡。
- 手動驗證確認更名送出中會顯示旋轉 icon，完成後會直接選到新商家或合併目標商家。
- 手動驗證更名後商家管理頁、交易列表、搜尋、統計與同步 payload 都會使用新名稱或合併後名稱。
