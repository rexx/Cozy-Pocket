# 統計頁類別篩選完成紀錄

統計頁篩選面板（漏斗圖示展開）除既有的 Tag 與支付方式外，加入了「類別」篩選，使用者可只看特定類別的統計結果。

篩選沿用面板現有的 chip row 形狀，以 `categoryId` 為值多選。選項只列出目前期間實際出現過的類別，依 `CATEGORIES` 既有順序（支出類別在前、收入類別在後）排列。篩選在既有的 `filteredTransactions` memo 內與 Tag、支付方式、子類別排除疊加，因此幣別總額、類別彙整、商家彙整、展開明細與趨勢圖全部保持一致。

實作只做唯讀的統計計算，不寫入 `transactions`、不碰同步 payload，屬於資料風險綠區。

---

## 最終行為

- 篩選面板由上而下為 `TAG`、`支付方式`、`類別` 三列 chip。
- 類別篩選為多選，採 **OR** 規則：交易只要屬於任一已選類別即納入。這與 Tag 的 AND 規則不同——一筆交易只有一個類別，AND 在此永遠得到空集合。
- 「全部」代表不限制，按下清空所有已選類別，並只在沒有任何已選類別時呈現選取樣式。
- 選項來源是目前期間（月／年／趨勢視窗）出現過的類別；切換期間時只丟掉該期間不再提供的選項，仍有效的選擇保留。
- 沒有 `categoryId` 的交易歸為「未分類」，可被單獨選取，並與目錄外的 id 一同排在清單最後。
- 幣別卡片右上的篩選徽章：選一個顯示類別名稱，多於一個顯示「N 個類別」。徽章組成順序為 tag、支付方式、類別、已排除子類別，與面板由上而下的順序相同。

## 實作內容

- `components/MonthlyStatsPage.tsx`
  - `selectedCategoryIds: string[]` state，搭配 `toggleCategory()` 與 `clearSelectedCategories()`。
  - `periodCategoryIds` memo 掃過 `periodTransactions` 收集出現過的 `categoryId`，以模組層的 `compareCategoryIdsByCatalogOrder` 依 `CATEGORY_ORDER_BY_ID` 排序，目錄外的 id 排最後。
  - prune effect 在期間改變後移除該期間不再存在的類別選擇，沿用 Tag 的「長度沒變就回傳原陣列」寫法保持 identity 穩定。
  - `filteredTransactions` 以 `selectedCategoryIdSet` 做成員判斷，與既有條件疊加。
  - `hasActiveFilters`、`activeFilterBadgeLabel` 與展開區塊 reset 的 dependency 都納入類別。
  - 篩選面板在支付方式之後新增類別 chip row，樣式與選中態沿用既有 class，未引入新色階。

`services/statsService.ts` 沒有變動：篩選發生在頁面層，`getCategoryStats()` 等既有純函式吃的就是篩過的交易。

## 附帶修正：趨勢圖空狀態文案

`MonthlyTrendChart` 原本以 `allCategoriesHidden` 為第一個判斷。當該幣別＋該收支類型在整個視窗內完全沒有資料時，`orderedCategoryIds` 與 `visibleCategoryIds` 同時為空，`allCategoriesHidden` 因而成立，畫面顯示「沒有選取任何類別」——把「沒有資料」誤報成「使用者自己取消了選取」，而 `近 N 個月沒有X紀錄` 這句成為不可達分支。

問題在 `main` 上即已存在，任何「有支出、沒收入」的期間切到收入分頁都會踩到；類別篩選讓它變得容易遇到（篩幾個支出類別再切收入就出現），因此一併修正。判斷順序改為先看 `hasAnyData`，三種空狀態各自對應正確文案。

## 與趨勢圖底部 chip 的關係

趨勢圖底部另有一排「類別 · 可多選」chip。兩者作用層級不同：

- 底部 chip 只決定那張圖要畫哪幾條色帶，狀態隨收支類型切換而重設、離開趨勢分頁即消失，且不影響總覽分頁。它同時是堆疊圖的圖例，排序與堆疊順序一致，chip 上附有該類別的 12 個月視窗總額。
- 篩選面板改變的是整頁的資料集，跨分頁保留，也影響總覽的彙整與明細。

兩者疊加時篩選先生效，chip 只能在剩下的類別裡挑。驗證中確認：同一組資料下「chip 只留飲食」與「篩選只勾飲食」得到相同的月均 132、最高月 1,435（8 月）、較上月 −90%，兩者在單一圖表內數值等價。這個重疊後續由[趨勢圖圖例改造](stats-trend-legend.md)處理。

## 驗證

- 自動檢查：`npm run build`（tsc strict + Vite production build）、`npm run docs:check`，皆通過。
- cmux 瀏覽器驗證（iPhone 寬度 390×844，範例資料 10 筆）：
  - 面板三列順序為 `TAG | 支付方式 | 類別`。
  - 單選「飲食」→ 支出 −$145、1 類別、1 商家，收入區塊整段隱藏。
  - 多選「飲食＋購物」→ 支出 −$2,495、2 類別，徽章顯示「2 個類別」。
  - 疊加支付方式「信用卡」→ 支出 −$2,350，徽章顯示「信用卡 · 2 個類別」。
  - 按「全部」清除類別條件後徽章退回「信用卡」，總額 −$2,570。
  - 9 月 → 8 月：選項換成該月實際存在的類別，仍有效的「飲食」保留。
  - 在 8 月加選「交通」後切回 9 月：9 月不存在的「交通」被移除，「飲食」保留。
  - 年份模式列出 8 個類別，順序為支出在前、收入在後。
  - 趨勢分頁篩選生效，圖表月均 107、最高月 1,280（8 月）。
  - 趨勢圖三種空狀態：篩掉全部支出類別再切收入 → 「近 12 個月沒有收入紀錄」（修正前誤報為「沒有選取任何類別」）；不篩選並在圖表按「取消全選」→ 「沒有選取任何類別」。

- 「目前選取的類別沒有資料」這個分支未能構造出來：`getMonthlyTrend` 只把有金額的類別放進 bucket，可見類別總額全為 0 的狀態可能本來就到不了。此分支的可達性不受本次修改影響。
