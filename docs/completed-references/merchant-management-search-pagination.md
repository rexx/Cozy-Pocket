# 商家管理搜尋與分頁完成紀錄

本項目已在 `merchant-management-search-pagination` worktree 完成，並合併回 `main`。

## 摘要

- 商家管理已加入即時搜尋與「載入更多商家」，降低大量商家 chip 的初次渲染成本。
- 第一版採用前端記憶體 filter 與 200 筆一批的增量顯示，暫不導入虛擬列表套件。
- 商家清單與相關交易列表都限制最高佔視窗高度一半，避免大量項目撐開整個管理頁。

## 已完成變更

- `MerchantManagementSection` 內部管理 `merchantSearchQuery` 與 `visibleMerchantCount`，不擴大父層 props 介面。
- 商家搜尋依商家名稱做即時 filter，支援清除搜尋。
- 商家摘要預設顯示前 200 筆；仍有更多結果時顯示「載入更多商家」，每次再增加 200 筆。
- 搜尋或商家摘要資料更新時，顯示數量會重設回第一批 200 筆。
- 選取商家後保留搜尋字串；若目前選取商家在搜尋結果中但不在可見批次內，會額外顯示「已選取」chip。
- 若目前選取商家不在搜尋結果中，頁面會提示清空搜尋可回到完整清單。
- 商家清單與選取商家的相關交易列表都使用 `max-h-[50vh]` 與內部捲動，避免大量項目撐開頁面。

## 介面與型別

- 不變更交易資料模型。
- 不變更 `MerchantManagementSection` 的外部 props；搜尋與分批顯示狀態由 section 內部管理。
- 不變更商家更名、預覽、交易點擊與同步相關 callback。

## 驗證

- 已執行 `npm run build`。
- 手動驗證搜尋可找到中文、英文、含空白商家名稱。
- 驗證清空搜尋、沒有結果、分頁載入更多與選取商家的狀態。
- 驗證商家清單與相關交易列表超過半個視窗高度時可在列表內捲動。
- 使用較大量測試資料檢查初次 render 與輸入搜尋時沒有明顯卡頓。

## 後續

- 若商家數量成長到 200 筆增量顯示仍不夠順暢，再評估導入虛擬列表。
- 若商家管理改為直接讀 IndexedDB，可再評估把搜尋條件下推到 service。
