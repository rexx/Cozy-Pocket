# 趨勢圖圖例改造計劃

> **給 agentic workers：** 本項目會使用新的 git worktree `worktrees/stats-trend-legend` 開發，不直接修改 repo 根目錄。前置條件：類別篩選（[stats-category-filter.md](../completed-references/stats-category-filter.md)）已合併進 `main`。

**目標：** 讓趨勢圖的圖例責任集中到焦點月讀數列表，並據此決定底部「類別 · 可多選」chip 列的去留。

**背景：** 統計頁篩選面板加入類別篩選後，chip 列的「挑類別」功能與頁面層篩選大量重疊；chip 列真正無可取代的是圖例與視窗總額兩件事。本項目要處理的是這個重疊，不是新增篩選能力。

**技術棧：** React 19、TypeScript strict、Tailwind CSS v4。

---

## 已確認的現況

實測與讀碼結果，作為設計前提：

- **chip 的篩選功能與頁面層篩選數值等價。** 同一組資料、支出分頁、只留「飲食」：兩種做法都得到 月均 132、最高月 1,435（8 月）、較上月 −90%、9 月讀數 −$145。柱子、Y 軸、三個 tile、焦點月讀數完全相同。
- **讀數列表目前不是完整圖例。** `MAX_READOUT_ROWS = 5`，超出的類別合併成一列「其他 N 個類別」，且該列用灰色 `bg-white/15` 而非各自的類別色，第 6 個以後的顏色對照因此斷掉。支出有 7 個類別，熱鬧的月份必然踩到。
- **兩份清單的排序基準不同。** 讀數列表按當月金額排序（`bucket.categories` 在 `getMonthlyTrend` 內排好）；堆疊色帶與 chip 列按 12 個月視窗總額排序（`orderedCategoryIds`）。後者是刻意的，避免色帶在相鄰月份之間跳位。
- **chip 上的金額是 12 個月視窗的類別總額。** 總覽分頁的「依類別彙整」只算當月或當年，全 app 沒有第二處提供滾動視窗的分類總額。移除 chip 列會失去這份資訊。

## 待決定

**chip 列的去留**，兩個方向擇一，取決於「12 個月每類各花多少」是否為實際會看的數字：

1. **整排移除。** 圖例責任完全交給改造後的讀數列表，視窗總額資訊放棄。畫面最省。
2. **降級為純圖例。** 保留顏色與視窗總額，移除點擊隱藏行為與全選／取消全選。資訊不減，但仍佔空間，且與讀數列表的圖例角色重複。

實作前先定案，不要兩者都做。

## 關鍵變更

- `components/stats/MonthlyTrendChart.tsx`
  - 讀數列表新增「顯示所有類別」切換：關閉維持現行行為（只列有金額的類別，保留 5 列上限與「其他」彙總）；開啟則列出視窗內全部類別，當月沒有的顯示 `$0`。
  - 開啟時排序改用 `orderedCategoryIds`（堆疊順序），讓圖例順序與色帶順序對齊。
  - 切換鈕取代 5 列上限：`$0` 項目必然排在金額末端，沿用上限會讓它們全部被吃進「其他」，切換就失去意義。
  - 依上方決議移除或降級 chip 列。

`services/statsService.ts` 不需要改：`getMonthlyTrend` 已提供每月每類別的資料，補 `$0` 屬於呈現層的事。

## UI 細節

- 切換鈕放在讀數列表標頭列右側，與「點長條可切換到其他月份」說明文字分開。
- `$0` 列的文字色階要比有金額的列更低，讓有金額的項目仍是視覺主體。
- 全部展開時 8 個類別約多佔 140px，卡片本身可捲動，不新增 fixed 元件或 safe-area padding。
- 沿用既有色階，不引入新顏色。

## 測試計劃

- 自動檢查：`npm run build`、`npm run docs:check`。
- 手動檢查：切換開關往返；當月類別數超過 5 個時「其他」列的行為；`$0` 列的排序與色塊對照；切換 支出／收入 與切月後開關狀態；與頁面層類別篩選疊加時圖例只剩篩選後的類別。
- 專案目前沒有測試框架，本項目不新增 runner。

## 假設

- 切換狀態只存在於本次 mount，不寫入 `localStorage` 或 Dexie。
- 「全部類別」的範圍是當前 12 個月視窗內出現過的類別，不是 `CATEGORIES` 全表。
- 本項目只做唯讀呈現，不寫入 `transactions`、不碰同步 payload，屬於資料風險綠區。
