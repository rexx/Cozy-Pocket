# App icon 造型評估紀錄：維持現行「口袋裡有錢幣」

**結論（2026-09-04）：不換。** 「錢幣騎在袋口上」的所有變體在 iPhone 上都拿不到 iOS 26 的 Liquid Glass 處理；字母 `C` 那一案通過，但要放棄「口袋」這個與 App 名字綁定的視覺資產，因此維持現行圖。

本紀錄留下實機結果，讓後續若重啟造型討論時不必重測。研究方法與判準見 [App icon 與 iOS 26 Liquid Glass](../app-icon-ios-liquid-glass.md)；探針原始檔（SVG ＋ 180px bitmap ＋ 掃描圖）在 `workdocs/app-icon-liquid-glass/evidence/probes-2026-09-04/`。

---

## 實機結果

判準是主畫面那格的背景色：系統補的深色 = 拿到處理，被壓成純白 = 沒拿到。每個變體放在各自網址、各自加到主畫面，避免 web clip icon 快取誤判。

## 為什麼 A 不能用

- **錢幣一離開輪廓就失效。** 橫線縫線下，`cy=132`（錢幣頂端突出輪廓外緣 34px）失效，`cy=170` 以下全部通過。A 的整個構想就是讓錢幣騎在袋口上，這一步在 iOS 這關過不去。
- **把袋口斷開讓位也救不了。** A 原案為了不讓兩塊實心相接而在錢幣兩側斷開袋口，結果空腔從 1 變 0、內周長 2.63 → 0.00，同樣失效。
- **縫線貼底部弧線本身就致命。** 錢幣固定 `cy=170`、只把縫線從袋口下方橫線搬到底部弧線，結果從通過變失效。所以 A 的縫線畫法連帶不能用，與錢幣位置無關。
- **最接近 A 的可用外觀是橫線縫線 ＋ `cy=170`**（錢幣高踞袋口內側）。它已驗證通過，但與現行圖的差異只有錢幣上移 88 個單位，視覺收益不足以換掉一張已經穩定的圖。

## 為什麼 C3 通過了也不採用

C3 是所有候選裡 16×16 最清楚、形狀最單純的一案，實機也拿到處理。代價是丟掉「口袋」——那是與 Cozy Pocket 這個名字綁定的視覺資產。這是造型取捨，不是技術限制。

## 已經試過、不要重畫的變體

| 變體 | 為什麼不行 |
|---|---|
| 錢幣置中懸在閉合袋口正上方 | 圓加圓角方是使用者頭像的標準剪影，會被讀成 avatar |
| 錢幣偏左懸在閉合袋口上方 | 避開頭像了，但口袋變成空桶，構圖散掉 |
| 日曆造型，其中一格是錢幣 | 32px 辨識度最好，但撞系統行事曆的長相，且跟 Cozy Pocket 這個名字脫鉤 |
| 環的缺口在右上、錢幣在缺口外 | 缺口朝右加右側一顆圓點是小精靈吃豆子的標準構圖 |

## 若未來重啟造型討論

1. 造型改動與實機驗證是綁在一起的一件事：沒有可以先算的判準，鄰近樣本的結果也不能外推（見參考文件 §3.3、§3.4）。
2. 每個候選給一頁獨立探針頁，不要直接把 `dist/` 掛在測試路徑下（參考文件 §6 有這個白屏陷阱的說明）。
3. 換圖後 `npm run icons:generate` 會印出內周長並與 baseline 比對，那是形狀指紋而非門檻；確認實機通過後才更新 `BASELINE_CAVITY_PERIMETER`。
4. 產出檔一併 commit —— GitHub Pages 部署不跑產出步驟。
