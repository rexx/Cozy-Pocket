# 統計頁分頁化實作計劃

本項目實作時會使用新的 git worktree 進行開發，不直接修改目前 repo 根目錄；建議 worktree 路徑為 `worktrees/stats-tabbed-layout`，完成後再由該分支提交與合併。

## 摘要

- 將統計頁內容改為頁內分頁，第一版提供「總計」與「依照類別統計」。
- 目標是降低單頁長度，讓未來加入依照商家、標籤等統計時有清楚的擴充位置。
- 月份／年份切換、tag、支付方式與後續子類別排除篩選維持在分頁上方，套用到所有統計分頁。

## 關鍵變更

- 在 `MonthlyStatsPage` 新增 active tab state，例如 `activeStatsTab: 'summary' | 'category'`。
- 在期間與篩選控制下方加入 segmented control，顯示「總計」與「依照類別統計」。
- 「總計」分頁保留目前各幣別的收入／支出總額卡與交易明細展開。
- 「依照類別統計」分頁只顯示目前的「依類別彙整」內容，包含支出類別、收入類別、子類別摘要與交易列表。
- 切換分頁時清除不適用的展開狀態，避免從總計切到類別統計後留下錯誤展開區塊。
- 保留未來 tab key 擴充點，例如 `merchant` 與 `tag`，但本項目不實作商家或標籤統計。

## 介面與型別

- 新增內部 union type，例如 `StatsTab = 'summary' | 'category'`。
- 不變更 `Transaction`、stats service 回傳型別或 persisted settings。
- 若後續商家統計實作，可沿用同一個 tab 結構掛載 `merchant` 分頁。

## 測試計劃

- 執行 `npm run build`。
- 手動驗證「總計」分頁只顯示收入／支出總額與交易明細展開。
- 手動驗證「依照類別統計」分頁只顯示類別統計內容，且類別展開、子類別摘要與交易點擊編輯仍正常。
- 驗證月份／年份、tag、支付方式與排除子類別篩選會同步影響兩個分頁。
- 驗證沒有資料、只有收入、只有支出與多幣別情境下，分頁空狀態與內容顯示合理。

## 假設

- 第一版分頁狀態不保存，離開統計頁再回來時可預設回到「總計」。
